## What it is

Native comments on story pages in the OTG Daily News site/app (github.com/365otg/otgdailynews). No third-party comments widget, no Disqus/Hyvor/Giscus branding, no ads in the discussion. Readers comment on OTG's own ground; every comment starts in an approval queue and only appears publicly after OTG approves it.

## How it works (user flow)

- A reader opens a story in the app's article preview (index.html `#article-view`). `app.js` `openArticle()` calls `window.OTGComments.open(postId, postUrl)` with the Blogger post ID taken from the feed entry's `id.$t` (`/post-(\d+)/`).
- `comments.js` renders into `#comments-section` (static fallback text shows if the module fails to load): "Discussion" heading with the approved-comment count, the moderation note, the approved-comments list (pinned first, then oldest first), and the comment form.
- The form asks for a name (2–40 chars) and a comment (2–1000 chars). Submitting creates a Firestore document with `status: 'pending'`. The reader sees "Thanks — your comment is waiting for review. It will appear here once OTG approves it." Pending comments are invisible to all readers.
- Approved comments render with author (Black), relative time, staff badge "OTG DAILY NEWS" (Crimson) for staff replies, "Pinned by OTG" label (Gold) for pinned comments, and staff replies nested under their parent via `parentId`.

## Security rules (v2) — STAGED, UNPUBLISHED

- Rules live in the Firebase console (Firestore → Rules) as v2, staged but NOT published as of November 7, 2026. Publishing waits on Charles's verdict. Do not publish without it.
- Collection `comments`:
  - `allow read: if resource.data.status == 'approved'` — readers only ever see approved comments.
  - `allow create` only with exactly the keys `['postId','postUrl','author','text','status','createdAt','pinned','staff','parentId','flagged']`, and `postId` string 1–200 chars, `postUrl` string ≤ 500, `author` 2–40 chars, `text` 2–1000 chars, `status == 'pending'`, `createdAt` is a timestamp, `pinned == false`, `staff == false`, `parentId == null`, `flagged` is a boolean.
  - `allow update, delete: if false` — no public update or delete. Moderation happens in the Firebase console, which bypasses rules.
  - Everything else is denied.
- Composite index: `comments` — `postId` ↑, `status` ↑, `createdAt` ↑ — Collection scope, Index ID `CICAgOjXh4EK`. It supports the approved-comments query (`where postId ==`, `where status == 'approved'`, `orderBy createdAt asc`, `limit 50`). It was created November 7, 2026 and was still Building at last check; confirm it shows Enabled in the console before relying on the query — until it is ready, the list shows "Comments could not be loaded."

## Moderation (in the Firebase console)

- Approve: set a pending comment's `status` to `approved`. Reject: delete the document (console bypasses rules). Spam: delete, and add its phrasing to the BLOCKLIST below.
- Pin: set `pinned: true` on an approved comment (it moves to the top with the Gold border and "Pinned by OTG" label).
- Staff reply: create a document with `staff: true`, `status: 'approved'`, `parentId: <parent doc id>` (to nest it under a comment), `pinned: false`, `flagged: false`, `author: "OTG Daily News"`, `postId`/`postUrl` matching the story, `createdAt: serverTimestamp()`. Staff comments are created in the console only, never from the public client.

## Word filters and spam rules (in comments.js)

- BLOCKLIST (refused at submit, no document is written): 'free money', 'crypto giveaway', 'double your bitcoin', 'click here to win', 'make money fast', 'earn $', 'send bitcoin', 'send btc'. The reader sees "That comment looks like spam and was not posted."
- HOLDLIST (flagged for review: `flagged: true`, still written as pending): 'scam', 'fake news', 'stupid', 'idiot', 'hate', 'kill'.
- Max 1 link per comment (more than 1 is refused).
- Rate limits (per browser, localStorage): 60 seconds between comments on the same story; max 5 comments per story per day. Keys `otg-comment-rate:<postId>` and `otg-comment-day:<postId>`.
- Honeypot: a hidden "website" field — a filled honeypot silently drops the submission.
- User text is rendered with `textContent` only, never `innerHTML` — no markup or script can be injected.
